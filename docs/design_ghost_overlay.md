## 0. 목적과 범위

### 0.1 무엇을 푸는가
회원이 셀프 운동할 때 **PT 때 트레이너가 찍어준 본인의 정자세 영상**을 카메라 프리뷰 위에 반투명으로 겹쳐, **자기 몸을 그 위에 맞춰가며** 운동하게 한다.

- **문제:** 지금은 영상을 "보고 → 기억하고 → 따라한다"는 3단계라 중간에 정보가 샌다. 폼이 틀어져도 본인은 모른다.
- **해결:** "보면서 동시에 맞춘다"로 단계를 1개로 줄인다. 카트라이더 고스트가 랩타임을 줄이는 원리와 같다 — **비교 대상이 같은 화면에 있으면 오차가 즉시 보인다.**
- 회원 가치: 셀프 운동의 폼 붕괴 방지 → 부상 감소·성장 체감 → 재등록 동기(변화추이 S1·영상 보관과 같은 결).
- 트레이너 가치: 수업 밖 시간에도 자기 코칭이 따라감. **이미 올린 영상의 가치가 재생 1회 → 반복 사용으로** 늘어난다(추가 업로드 노동 0).

### 0.2 왜 지금 할 만한가 (비용 대비)
| | 본 기능 |
|---|---|
| 신규 테이블·마이그레이션 | **0** — 기존 `class_videos`(0027) 그대로 |
| 신규 스토리지·전송 비용 | **0** — 기존 서명 URL 재생 경로 재사용 |
| 촬영물 저장 | **없음**(§4) → 신규 동의 항목 0 |
| 신규 의존성 | **`camera` 1개**(G1 기준). ML Kit 불필요 |
| 외부 전송 | **0** — 전부 기기 안 |

→ 이미 깔아둔 인프라(영상 업로드·서명URL·권한) 위에 **재생 UI만** 얹는 구조라, 피드백 대비 회수가 가장 빠른 항목이다.

### 0.3 베타 범위 (스코프 가드)
- 대상 영상 = **회원 본인의 `class_videos`**(트레이너가 그 회원을 찍어 올린 것). RLS·서명URL 경로 그대로.
- **보기 전용**: 겹쳐 보여주기만 하고 **녹화·저장·업로드 없음**(§0.4).
- 진입점 = 회원 영상 목록(`/member/videos`)의 각 영상 → "따라하기".
- 정렬은 **수동**(핀치줌·드래그·좌우반전)으로 시작 — 자동 정렬은 G3(§6).

### 0.4 비범위 (후순위/별트랙)
- **오버레이 상태 그대로 녹화**: `camera` 의 녹화는 프리뷰 텍스처만 담아 **오버레이가 안 들어간다**. 합성 녹화는 네이티브 인코딩(또는 FFmpeg)이 필요 → 4.6에서 재인코딩을 피한 것과 같은 이유로 **비범위**.
- 회원 셀프 영상 업로드·저장: `class_videos` 는 트레이너 업로드 전용(설계 §9.4) — 유지.
- 실시간 자세 채점·렙 카운트: 4.5 R&D 트랙.
- 타인(트레이너 시범) 영상 고스트: 체형이 달라 정렬 난이도↑ → 본인 영상 우선.

## 1. 이 기능의 진짜 난이도 (정직하게)

카트라이더 고스트가 깔끔하게 겹치는 건 **같은 트랙·같은 카메라 규격**이기 때문이다. 운동 영상은 그 전제가 없다:

| 어긋나는 축 | 결과 | 대응 |
|---|---|---|
| 카메라 **거리·높이·각도** | 몸 크기·원근이 안 맞음 | 수동 핀치줌·드래그 정렬(G1) + 촬영 가이드 재사용(4.1) |
| **좌우 반전** (전면카메라는 거울상, PT영상은 후면카메라 촬영) | 좌우가 뒤집혀 보여 오히려 혼란 | **좌우반전 토글 필수**(`Transform(scaleX:-1)`) — G1 필수 기능 |
| **템포** (그날 컨디션에 따라 속도 다름) | 동작이 어긋나 따라가기 불가 | 재생속도 0.25~1.0x + **구간 반복(A-B 루프)** |
| **배경·옷차림** | 반투명 영상의 배경이 시야를 어지럽힘 | 불투명도 조절 + G2에서 **스켈레톤만** 남기기 |

> **결론:** "겹치면 알아서 맞는다"는 순진한 가정은 틀렸다. **정렬·템포·반전을 사용자가 통제할 수 있게 만드는 것이 이 기능의 본체**이고, 반투명 합성 자체는 쉬운 부분이다. G1 설계가 여기에 집중하는 이유.

## 2. 기술 구조

### 2.1 화면 합성 (G1)
```
Stack
 ├─ CameraPreview(controller)                     ← 후면/전면 실시간 프리뷰 (바닥)
 ├─ Transform(scale/translate/flipX)              ← 사용자가 맞춘 정렬
 │    └─ Opacity(0.2~0.6)
 │         └─ AspectRatio → VideoPlayer(ghost)    ← PT 영상 (반투명)
 └─ 컨트롤 레이어(불투명도·속도·반전·루프·재생)
```
- 두 개의 **네이티브 텍스처를 동시 렌더**하는 구조 → 저사양 기기 프레임드랍·발열이 최대 성능 리스크. **PoC 선행**(§7).
- 프리뷰 해상도는 `ResolutionPreset.medium` 정도로 낮춘다(녹화가 없으므로 화질보다 프레임 안정이 중요).

### 2.2 정렬 조작 (핵심 UX)
- **핀치줌 / 드래그**: 고스트 영상의 `scale`·`offset` 조정. `InteractiveViewer` 대신 `GestureDetector(onScaleUpdate)` + `Transform` — 프리뷰는 고정하고 **고스트만** 움직여야 하므로.
- **좌우반전 토글**: 전면카메라 사용 시 기본 ON 권장(거울상 보정).
- **정렬 초기화** 버튼: 어긋났을 때 1탭 복귀(되돌릴 수 없는 조작이 없어야 함).
- **정렬값 기억**: 영상별로 `shared_preferences`(이미 도입됨)에 `{videoId: {scale, dx, dy, flip, opacity}}` 저장 → 다음에 같은 영상 열면 그대로. **서버 저장 0.**

### 2.3 재생 제어
- 불투명도 슬라이더(기본 0.35), 재생속도(`setPlaybackSpeed` 0.25/0.5/0.75/1.0x), **A-B 구간 반복**(1렙만 무한 반복 — 실사용에서 가장 중요), 음소거 토글.
  - 음성은 **끄지 말고 기본 ON 권장** — 트레이너 코칭 육성이 담겨 있으면 그 자체가 개인화 피드백이다.
- 화면 꺼짐 방지: 운동 중 조작이 없으므로 필요. `wakelock_plus` 의존성 추가 vs 미도입(사용자가 화면 시간 늘리기) — §8 미해결.

### 2.4 앱 구조 (co-locate)
- `features/videos/ghost_overlay_screen.dart` — 공용 화면(회원/트레이너 둘 다 진입 가능하게). 기존 `class_video_player.dart` 와 **같은 규약**: Supabase/Riverpod 비의존, 호출 측이 서명 URL 을 해석해 넘긴다.
- `features/videos/ghost_alignment.dart` — 정렬 상태 모델 + `shared_preferences` 영속화.
- `domain/ghost_alignment_state.dart` — 정렬값 클램프(과도한 확대/이탈 방지) 순수 함수 + **단위테스트**(develop_plan §5.1 원칙).
- 진입: `features/member/videos/screen.dart` 타일에 "따라하기" 액션 추가(기존 재생과 **병렬** — 기본 재생은 그대로 둔다).

### 2.5 의존성 (★ develop_plan §0 표 갱신 필요)
| 패키지 | 용도 | 비고 |
|---|---|---|
| `camera` | 실시간 프리뷰 | **체형분석 4.1 촬영 가이드와 공유** — 한 번 도입해 두 트랙이 쓴다. 카메라 권한 문구(AndroidManifest/Info.plist) 필요 |
| (`video_player` 재사용) | 고스트 재생 | 0027에서 이미 도입 |
| (`shared_preferences` 재사용) | 정렬값 기기 저장 | PT 알림에서 이미 도입 |
| (`google_mlkit_pose_detection`) | **G2 이후만** | 체형분석(4.2)·트래킹(4.6)과 공유 |

## 4. 프라이버시 (신규 동의 불필요한 이유)

- 카메라 프리뷰는 **화면에 그리기만** 하고 **파일로 저장하지 않으며 기기 밖으로 나가지 않는다.** 촬영물이 생기지 않으므로 신체사진 동의(`body_photo_consent`, 체형분석 §3.4)나 영상 동의(0027) **대상이 아니다.**
- 고스트로 재생되는 영상은 **회원 본인이 이미 열람 권한을 가진 자기 영상** — 노출 범위가 넓어지지 않는다.
- 단, **카메라 권한 요청 문구**는 필요: "운동 자세를 화면에 비추기 위해 사용하며, 촬영·저장하지 않습니다." (iOS 심사 §6 체크리스트 "Camera 권한 사용 목적 명시" 충족)
- G2(스켈레톤) 도입 시에도 ML Kit 은 온디바이스라 외부 전송 0 — 체형분석·트래킹과 동일 논리.

## 5. 단계적 구현 계획

- **PoC(선행, 필수)** — `CameraPreview` + `VideoPlayer` **동시 렌더가 실기기에서 성립하는지**(프레임·발열·초기화 충돌). 여기서 막히면 전체 재설계. → 상위 계획 §0단계와 묶어 진행.
- **G1. 수동 고스트 (MVP)** — 반투명 합성 + 정렬(핀치줌·드래그·좌우반전·초기화) + 재생제어(불투명도·속도·A-B루프·음소거) + 정렬값 기기 저장. **ML Kit 불필요, 마이그레이션 0.** ← 피드백을 가장 빨리 회수하는 지점.
- **G2. 스켈레톤 고스트** — 영상에서 pose 를 뽑아 **사람 대신 관절 선만** 오버레이. 배경 노이즈 0 + 체형 차이 영향↓. **4.6의 프레임추출 PoC 결과에 종속**(같은 관문).
- **G3. 자동 정렬 + 실시간 차이 표시** — 내 실시간 pose 와 고스트 pose 를 어깨·골반 기준으로 자동 스케일/정렬, 관절각 차이를 색으로 표시("무릎 각도 차이 큼"). **단정 금지 톤**(체형분석 §1.3과 동일 원칙).
- **G4(별트랙).** 셀프 촬영 영상 vs PT 영상 나란히 비교(사후 복기). 녹화 합성이 아니라 **두 영상 동시 재생**이라 §0.4 제약을 피함.

각 단계 끝: analyze/test/build 통과 + develop_plan 갱신(프로젝트 규칙).

## 6. 미해결 결정 (구현 전 확정 필요)

1. **전면 vs 후면 카메라 기본값**: 전면=본인이 화면을 보며 조정 가능하지만 거울상·화질↓. 후면=화질↑이지만 화면을 못 봄(거치 필요). → **전면 기본 + 전환 버튼**이 현실적.
2. **화면 꺼짐 방지**: `wakelock_plus` 도입 vs 미도입(안내만). 의존성 최소 원칙과 UX 충돌.
3. **정렬값 저장 위치**: 기기 로컬(제안) vs 서버(`class_videos` 컬럼). 기기별 카메라가 달라 **로컬이 타당**하나 기기 교체 시 유실.
4. **A-B 루프 UI**: 슬라이더 2핸들 vs "여기서 시작/여기서 끝" 2탭. 운동 중 조작이라 **탭 방식**이 유리해 보임.
5. **트레이너 진입 허용 여부**: 트레이너가 수업 중 시연용으로 쓸지. 공용 화면이라 라우팅만 열면 됨.
6. **저사양 기기 폴백**: PoC 결과 프레임이 안 나오면 "프리뷰 해상도 낮춤" vs "기능 숨김".

## 8. 요약

- **한 문장**: 이미 올라간 회원 본인의 PT 영상을 카메라 프리뷰 위에 **반투명으로 겹쳐** 보여주고, 정렬·템포를 사용자가 통제하게 해서 "보고 기억해서 따라하기"를 "보면서 맞추기"로 바꾼다 — **DB·저장·전송·동의 추가 0.**
