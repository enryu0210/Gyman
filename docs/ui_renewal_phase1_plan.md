## 1. 결론

GYMAN의 현재 브랜드인 **잉크 블랙 + 볼트 라임**은 유지한다. 다만 홈 화면을
기능 바로가기의 집합에서, 사용자가 매일 열어 즉시 업무를 처리하는 **역할별 앱 셸**로
전환한다.

1차 개편의 목표는 다음 세 가지다.

1. 트레이너가 앱을 열자마자 **다음 수업과 오늘의 업무**를 파악한다.
2. 수업 직후 **기록하기**로 즉시 진입한다.
3. 주요 기능을 홈의 격자에서 찾지 않고 **고정 하단 탭**으로 이동한다.

이번 개편은 기능·DB·권한 정책을 바꾸지 않는다. 이미 있는 기능을 더 빠르게 찾고
처리하도록 정보 구조와 화면 흐름을 개선하는 작업이다.

## 2. 현재 화면에서 유지할 점과 개선할 점

### 유지할 점

- `Ink + Volt` 브랜드 색상과 Pretendard 서체
- 카드의 얇은 테두리, 과도한 그림자를 쓰지 않는 표면 스타일
- 트레이너 홈의 처리 대기 요약과 재등록 알림
- 회원 홈의 출석 스트릭, 다음 수업, 잔여 횟수
- 안 읽음·승인 대기처럼 즉시 처리해야 하는 상태 배지

### 개선할 점

| 현재 인상 | 개선 방향 |
|---|---|
| 홈에 기능 진입점이 집중돼 있어 설정 화면처럼 느껴질 수 있음 | 주요 기능은 하단 탭으로 고정하고, 홈은 오늘의 업무에 집중 |
| 트레이너 홈의 첫 정보가 처리 대기 총량 | 다음 수업과 오늘 일정 타임라인을 최상단으로 승격 |
| 수업 기록 진입점이 다른 메뉴와 같은 무게 | 가운데 강조 버튼으로 수업 직후 동선을 단축 |
| 역할별 핵심 흐름이 화면 단위로 분산 | 트레이너와 회원 각각의 반복 사용 흐름을 기준으로 재구성 |

## 3. 1차 개편 범위

### 3.1 트레이너 앱 셸

트레이너의 하단 탭은 아래 다섯 개로 구성한다.

| 탭 | 목적 | 연결 기능 |
|---|---|---|
| 홈 | 지금 처리할 업무와 다음 수업 확인 | 트레이너 홈 |
| 회원 | 회원 검색·목록·상세 진입 | 회원 목록 |
| 기록하기 | 수업 기록을 가장 빠르게 시작 | 회원 선택 또는 현재 수업의 기록 화면 |
| 일정 | 예약 관리와 승인 요청 처리 | 예약 화면 |
| 채팅 | 회원 대화와 안 읽음 메시지 처리 | 트레이너 채팅 목록 |

`기록하기`는 다른 탭보다 시각적으로 강조한다. 볼트 라임의 가운데 버튼 또는
하단 바 위로 살짝 올라온 형태를 사용하되, 접근성·안전 영역·작은 화면에서의
터치 영역을 함께 검증한다.

AI 검수는 별도 하단 탭으로 두지 않는다. 홈의 처리할 일 및 알림 진입점에서 접근하게
하여, 항상 처리해야 하는 핵심 업무처럼 보이지 않도록 한다.

### 3.2 트레이너 홈 재구성

트레이너 홈의 정보 우선순위는 아래와 같다.

1. 다음 수업
2. 오늘의 수업 타임라인
3. 처리할 일
4. 재등록 주의 회원
5. 보조 바로가기

권장 와이어 구조는 다음과 같다.

```text
[날짜]                                      [알림] [설정]

안녕하세요, 민서 트레이너님
오늘 수업 3건 · 처리할 일 5건

┌ 다음 수업 — 14:00, 32분 후 ──────────────────────┐
│ 김민수 · 잔여 8회 · 어깨 불편 메모 있음             │
│ [회원 카드]                         [수업 기록]    │
└─────────────────────────────────────────────────┘

오늘의 타임라인
14:00  김민수      예정
16:00  이수진      잔여 3회 · 주의
19:00  박지훈      기록 완료

처리할 일
[예약 승인 2] [AI 검수 2] [안 읽은 채팅 1]

재등록 주의 회원
최예린 · 잔여 1회 · 만료 D-3                       [메시지]
```

다음 수업이 없는 날에는 큰 빈 영역을 남기지 않는다. "오늘 예정된 수업이 없어요"와
`예약 추가` 행동을 함께 제시하고, 처리할 일 또는 재등록 섹션을 위로 올린다.

### 3.3 회원 앱 셸 (후속 적용 후보)

회원용 하단 탭은 아래 구성을 기본안으로 둔다.

| 탭 | 목적 |
|---|---|
| 홈 | 다음 PT와 이번 주 운동 현황 |
| 일정 | PT 예약과 출석 확인 |
| 기록 | 수업 기록·셀프 운동 기록·변화 추이 |
| 채팅 | 트레이너와 대화 |
| 내 정보 | 계약, 영상, 공지, 설정 등 보조 기능 |

회원 홈의 첫 화면은 잔여 횟수보다 운동 경험을 먼저 보여준다.

1. 다음 PT 또는 오늘의 운동
2. 트레이너 메시지 또는 안내
3. 이번 주 운동 목표·출석 현황
4. 최근 변화 요약
5. 계약 잔여 횟수와 보조 메뉴

회원 앱 셸은 1차 트레이너 개편의 구조가 검증된 뒤 적용한다. 따라서 이번 구현 범위에는
포함하지 않되, 공통 네비게이션 구조는 재사용 가능하게 설계한다.

## 4. 시각 디자인 원칙

### 4.1 강조 규칙

- 화면마다 가장 중요한 행동은 한 개만 볼트 라임으로 강조한다.
- 잉크 블록은 트레이너의 집중 정보(다음 수업, 처리 대기 요약)에만 사용한다.
- 경고 상태는 색상만으로 판단시키지 않는다. `잔여 1회`, `만료 D-3`처럼 텍스트를 항상 병기한다.
- 일반 목록은 카드를 과도하게 반복하지 않고, 시간·상태·행동이 빠르게 읽히는 리스트 또는 타임라인을 사용한다.

### 4.2 실제 서비스 사용감에 필요한 공통 요소

- 탭 전환 뒤에도 탭별 스크롤 위치와 목록 상태를 유지한다.
- 하단 탭의 안 읽음·승인 대기 배지는 실제 데이터와 연결한다.
- 로딩 중에는 큰 빈 화면 대신 카드 크기에 맞춘 스켈레톤을 보여준다.
- 빈 상태에는 설명과 함께 즉시 실행할 행동을 제공한다.
- 오늘 수업은 시간이 흐르면서 `다음 수업`, `진행 중`, `기록 완료` 상태로 자연스럽게 바뀌어야 한다.

## 5. 구현 순서

### 단계 A — 공통 기반

1. 역할별 하단 탭을 담는 앱 셸을 만든다.
2. 탭 전환 시 상태 보존 방식과 뒤로 가기 정책을 정한다.
3. 현재 라우트를 탭 루트와 상세 화면 드릴인으로 구분한다.
4. 하단 탭의 배지 데이터 연결 방식을 정리한다.

### 단계 B — 트레이너 핵심 흐름

1. 트레이너 홈 최상단에 다음 수업 카드를 추가한다.
2. 오늘 수업을 시간 순 타임라인으로 표시한다.
3. 가운데 `기록하기`에서 현재·다음 수업 또는 회원 선택으로 연결한다.
4. 기존 처리 대기와 재등록 알림은 하단 섹션으로 재배치한다.

### 단계 C — 품질 확인

1. 수업 없음, 계약 없음, 대기 업무 없음, 안 읽음 없음 상태를 확인한다.
2. 작은 화면과 다크 모드에서 하단 바·가운데 버튼·긴 회원명을 확인한다.
3. 탭 간 이동, 상세 진입, 뒤로 가기에서 이전 맥락이 유지되는지 확인한다.
4. 기존 예약·수업 기록·채팅·AI 검수 기능의 라우팅 회귀 테스트를 수행한다.

## 6. 1차 완료 기준

- 트레이너가 홈에서 다음 수업을 한 번에 확인할 수 있다.
- 트레이너가 어느 탭에서든 두 번 이내의 조작으로 수업 기록을 시작할 수 있다.
- 회원·예약·채팅은 홈으로 돌아가지 않고 하단 탭에서 이동할 수 있다.
- 기존 권한 분리, 수업 기록, 예약 승인, AI 검수 흐름이 깨지지 않는다.
- 라이트·다크 모드 모두에서 볼트 라임 텍스트 대비 규칙을 지킨다.
