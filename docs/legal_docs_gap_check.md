## A. 정책이 사실과 다름 (가장 위험)

### A-1. 탈퇴해도 사진·영상·채팅이 그대로 남는다 ⚠ 최우선

**정책 문안**
> 3. 개인정보의 보유 및 이용 기간
> - 회원 탈퇴 시 개인정보(이름·연락처 등 식별정보)는 **즉시 익명 처리**합니다.
> - 수업 기록·계약 등은 **식별정보를 제거한 형태로** 통계 목적상 보존될 수 있습니다.

**실제 동작** (`functions/delete-account/index.ts`)
탈퇴가 건드리는 테이블은 **`member_profiles` 단 하나**다. 지우는 값은
`name / phone / birth_date / goal / experience / injury_history / body_features /
lifestyle / available_times` + `user_id=NULL` + `deleted_at`.

그대로 남는 것:

| 남는 데이터 | 어디 | 왜 문제인가 |
|---|---|---|
| **체형 사진** | `body-photos` 버킷 (0039) | **사진 자체가 식별정보다.** "식별정보를 제거한 형태"가 성립하지 않는다. 건강·신체 정보라 민감정보이기도 하다 |
| **수업 영상** | `class-videos` 버킷 (0027) | 회원이 운동하는 모습이 찍힌 영상. 위와 동일 |
| **채팅 내용·이미지** | `messages`, `chat-images` (0024·0026) | §1 이 "채팅 내용"을 **수집 항목으로 명시**해놓고 파기 대상에서 빠졌다 |
| **인바디 측정값** | `body_measurements` (0023) | 건강정보. `member_id` FK 로 프로필 행과 계속 연결됨 |
| **트레이너 메모** | `member_notes` (0004) | 회원에 관한 서술. 회원에게는 비공개 |
| **회원 셀프 기록** | `self_workout_logs` (0028) | — |

`member_profiles` 는 **soft delete**(`deleted_at`)라서 `ON DELETE CASCADE` 가 영영 발동하지 않는다.
즉 "언젠가 정리되겠지"가 아니라 **영구히 남는다.**

**선택지**
1. **탈퇴 시 스토리지 3종 + 채팅을 실제로 삭제**하도록 `delete-account` 확장 (권장)
2. 삭제가 어렵다면 문안을 사실에 맞게 낮춘다 — 단 "체형 사진이 탈퇴 후에도 보관된다"를
   회원이 납득할 이유가 필요하고, 그건 문안보다 **동의 시점의 고지** 문제가 된다

> ⚠ 1번을 택할 때 주의: 수업 영상·채팅은 **트레이너에게도 자산**이다.
> 회원 탈퇴로 트레이너의 수업 기록이 통째로 사라지면 그건 그것대로 사고다.
> "회원이 올린 것"과 "트레이너가 올린 것"을 나눠서 판단해야 한다.

### A-2. AI 동의의 주체가 회원이 아니라 트레이너다

**정책 문안**
> 4. 개인정보의 제3자 제공
> - AI 기능 사용 시 … **회원이 AI 사용에 동의한 경우에만** 적용됩니다.

**실제 동작**
`ai_consent` 를 켜는 UI 는 **트레이너의 회원 수정 다이얼로그에만** 있다
(`edit_member_dialog.dart:270`). 회원 본인 화면에는 이 값을 **보는 기능도, 끄는 기능도 없다**
(`features/member/`·`features/settings/` 검색 결과 0건).

코드 주석은 이 구조를 정직하게 인정하고 있다:
> 동의의 주체는 회원이고 입력 주체는 트레이너 — "회원에게 동의를 받았다"를 트레이너가 대신 기록

문제는 **정책 문안이 그 사실을 감춘다**는 점이다. "회원이 동의한 경우에만"은
회원이 앱에서 직접 동의했다고 읽히는데, 실제로는 트레이너가 오프라인 동의를 주장하며 켠 체크박스다.
회원 입장에서는 **본인 수업 기록·인바디가 외부 LLM 으로 나가는지 확인할 방법이 없다.**

**선택지**
1. 회원 설정에 AI 동의 토글 추가 + 회원이 끄면 트레이너가 못 켜게 (권장, 작업량 작음)
2. 최소한 회원 화면에 **현재 상태를 표시**라도 할 것
3. 문안을 "트레이너가 회원의 동의를 확인한 경우"로 정정

## C. 구조적 공백 — 동의를 받을 수 없는 사람의 개인정보

**앱에 가입하지 않은 회원이 존재한다.** 0013 이후 `member_profiles.user_id` 는 nullable 이고,
트레이너가 회원을 대신 등록할 수 있다(0014, `created_by_trainer_id`).

그 사람에 대해 트레이너가 입력하는 것: **이름·전화번호·생년월일·부상 이력·체형 특징·생활 패턴**,
그리고 인바디·체형 사진·수업 영상까지.

그런데 그 사람은:
- 이용약관·개인정보 처리방침을 **본 적이 없다** (앱을 안 깔았으므로)
- `user_consents` 에 **행이 없다** (PK 가 `auth.users.id` 라 계정 없이는 기록 자체가 불가능)
- 이용약관 제2조의 "회원" 정의(**초대 코드로 계정을 연결한** 이용자)에 **해당하지 않는다**
  → 약관상 아무 지위도 없으면서 개인정보만 처리되는 상태

이건 문안 수정으로 닫히지 않는다. 실무적으로는 **트레이너가 오프라인으로 동의를 받는 것**을
전제하게 되는데, 그렇다면 최소한:
- 회원 등록 화면에 "회원 본인에게 수집·이용 동의를 받았음"을 트레이너가 확인하는 게이트
- 그 확인 사실의 기록(누가·언제)
- 오프라인 동의서 양식 제공

가 있어야 한다. **현재는 셋 다 없다.** (A-2 의 AI 동의와 같은 구조의 문제다)
