**버튼 동작**
| 버튼 | DB 상태 전이 | 효과 |
|------|-------------|------|
| **발송 취소** | `status='canceled'` | 발송 큐에서 제외 |
| **내용 수정** | (저장 시) `status='draft'` 유지하되 `content` 갱신 | 다시 검수 화면 표시 |
| **발송 승인 ✓** | `status='approved'`, `approved_at=now()` | 예약 시각 도달 시 자동 발송 |

> CHECK 제약 (`data_model §2.2`): `status='sent'`는 반드시 `approved_at IS NOT NULL` 필요.
> 즉 **트레이너 승인 없이 sent로 전이될 수 없음 — DB 레벨에서 강제**.

**버튼 동작**
| 버튼 | DB 상태 전이 | 효과 |
|------|-------------|------|
| **삭제 🗑** | row 삭제 또는 `source='ai_draft'`인 채로 hard delete | 메모 영역에 안 보임 |
| **수정** | (저장 시) `content` 갱신, `source='ai_draft'` 유지 | 재검수 |
| **확정 저장 ✓** | `source='ai_confirmed'`, `confirmed_at=now()` | 회원 카드 메모 영역에 표시 (트레이너 전용) |

> RLS 차원: `member_notes`는 `source` 무관하게 회원 SELECT 자체가 차단됨 (`notes_member_deny` 정책).
> 따라서 ai_draft든 ai_confirmed든 **어떤 상태에서도 회원에게 노출되지 않음.**

## 설계 의도

### 1. 검수 화면 = AI 안전 게이트
- 발송/확정 버튼이 명확히 분리되어 트레이너의 **명시적 의사결정 행위**를 요구
- "한 번 더 보세요" 텍스트로 책임 환기

### 2. 일괄 처리는 제공하되 추적
- 트레이너 시간 절약을 위해 "모두 승인" 제공
- 단, 일괄 승인 비율이 너무 높으면 (예: >80%) 검수가 형식적이라는 신호
- Analytics로 추적해서 prompt 품질 개선 트리거로 활용

### 3. ←/→ 네비게이션
- 검수 대기 N건을 한 번에 처리할 수 있도록 좌우 화살표 제공
- 5건 메모 검수 = 1분 미만 목표

### 4. AI 생성 정보 표시
- 어떤 모델·언제·무엇을 입력으로 만들었는지 항상 표시
- Audit 일관성 + 트레이너의 신뢰 형성
- `outgoing_notifications.ai_prompt_snapshot`, `member_notes.source_session_id` 활용

### 5. "AI 원본으로 되돌리기"
- 수정 중 실수로 잘못 지웠을 때 복구
- 원본은 별도 컬럼에 보관 (또는 audit log에서 조회)
- 데이터 모델 후속: `outgoing_notifications.ai_original_content text` 추가 검토

### 6. 메시지 검수의 "발송 채널 변경" 옵션
- 일부 회원은 FCM 푸시를 끈 상태일 수 있음
- 카카오 알림톡으로 폴백 옵션 (Phase 1 후반 카카오 연동 시)
- 데이터 모델: `outgoing_notifications.send_channel` 활용
