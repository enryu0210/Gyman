## 1. 자료 수집 — 운톡 실제 불만 (리뷰 원문 기반)

운톡은 **회원용**(`운톡`)과 **트레이너/센터용**(`운톡 관리자`) 두 앱으로 나뉜다.
강제 설치 구조라 자발적 사용 의지가 낮고, 두 앱 모두 평점이 낮다.

### 1.1 회원용 앱 — App Store 2.3 / Google Play 2.5 (203개 평가)

| 분류 | 리뷰 원문 (발췌) |
|------|------|
| 달력 버그 | "하단 독바의 두번째 메뉴 클릭시, 이전 달력으로 넘기면 **일자가 반만 보여요**. 말일까지 안보이고.. 수정해주세요" |
| 탈퇴 불가 | "센터에서 등록해주는거 아니면 **메인 화면조차 볼 수가 없어서 탈퇴를 할 수가 없습니다**" |
| 가시성 | "**순위에서 제가 명확하게 안 보이는 것 같아서**" (랭킹/내 위치 가독성) |
| 계정 복구 | 탈퇴 후 재가입 시 **문자(SMS) 인증이 안 됨**, 아이디·비번 찾기 불가, 소셜 로그인 없음 |
| 출석 기록 | 출석/운동 기록을 **일주일 단위로만** 조회, 전체 히스토리 없음 |
| 지원 채널 | 앱 내 **문의할 곳이 없어** 리뷰란에 민원, 수정 요청 묵묵부답 |
| 동기부여 | 변화 추이·성취감 피드 부재 |
| 사생활 | (카톡 대체 시) **시간대 무관 알림**으로 사생활 침해 |

## 5. 항목별 실행 계획

### A. 계정 설정 + 탈퇴 플로우 (P0)

**왜:** 운톡 최악 불만. "빠져나갈 자유"가 없으면 강제 설치 앱과 다를 게 없다. 스토어 심사도 탈퇴 경로를 요구.

**UX (목표: 탈퇴까지 3탭 이내)**
1. 홈/하단 메뉴 → `설정` 진입
2. 설정 화면: 알림 설정 / 문의하기 / 개인정보 처리방침 / **회원 탈퇴**(하단, 위험색)
3. 탈퇴 → 사유 선택 + "데이터 삭제 안내" 다이얼로그 → 확인 → 처리 → 로그아웃

**구현 (Supabase 스택 주의):**
- **탈퇴는 `anon` 키로 불가** — `auth.users` 삭제는 service_role(admin API) 필요.
  → **Edge Function `delete-account`** 신설(`verify_jwt=true`). 호출자 JWT 검증 후 service_role로:
  1. 본인 `member_profiles` 행 **익명화 또는 hard delete** (개인정보 처리방침 §9 준수)
  2. 연결된 회원 데이터 처리(세션/기록은 트레이너 자산이므로 **익명화 권장**, PII만 제거)
  3. `auth.admin.deleteUser(uid)` 로 계정 삭제
  - 보상 트랜잭션 원칙(CLAUDE.md): 프로필 처리 성공 후 auth 삭제 실패 시 롤백/재시도 로그.
- 마이그레이션: 탈퇴 사유 수집 테이블(선택) `account_deletion_logs` + RLS.
- 클라: `features/settings/settings_screen.dart`, `delete_account_dialog.dart`, `settings_repository.dart`(Edge Function invoke), 라우트 `/settings` 추가.

**테스트 기준:** 설정→탈퇴까지 3탭 / 탈퇴 후 동일 계정 재로그인 차단 확인 / 트레이너 화면에서 탈퇴 회원 PII 비노출.

### B. 앱 내 문의 채널 (P0)

**왜:** 운톡은 창구가 없어 리뷰란이 민원게시판이 됨. 별점 테러 방지선.

**구현 (최소 규모):**
- 설정 화면(A)에 "문의하기" 항목.
- 1차: `url_launcher` 의 `mailto:` 로 운영 이메일 연결(제목·앱버전·역할 자동 채움).
  - `url_launcher` 는 이미 의존성에 존재(KGP 경고 항목) → **신규 의존성 0**.
- 센터별 문의처가 필요하면 `centers` 에 `contact_email` 컬럼 추가(마이그레이션 + 트레이너/관리자 read).

**테스트 기준:** 설정 > 문의하기 항상 노출 / 탭 시 메일 앱에 앱버전·계정역할 프리필.

### C. 출석 캘린더 뷰 + PT/셀프 색 구분 (P1)

**왜:** 운톡 핵심 불만(일주일만 조회) 직격. "6개월 전 기록 조회 가능"이 목표.

**현재:** `member_records_screen` 은 done 세션 **리스트**(전체기간 O). 캘린더 형태·셀프운동 통합·색 구분이 없음.

**구현:**
- 데이터 소스 2개 병합: PT 출석(`sessions` done) + 셀프(`self_workout_logs`). 날짜별 type 마킹.
  - 리포지토리에서 월 범위로 두 테이블 조회 후 `Map<DateTime, {pt, self}>` 병합.
- 뷰: 월 단위 캘린더. **의존성 결정 필요** (아래 §6 리스크):
  - (권장) 경량 커스텀 월 그리드 — 신규 의존성 0, 달력 버그 통제 쉬움
  - (대안) `table_calendar` 도입 — 빠르지만 develop_plan §0 의존성 표 갱신 필요
- 날짜 탭 → 기존 상세 바텀시트 재사용. PT=블루, 셀프=오렌지 점 마킹.

**테스트 기준:** 6개월 전 날짜 조회 / PT·셀프 시각 구분 / 구형 기기(갤S21, iPhone SE2)에서 레이아웃 깨짐 없음.

## 6. 리스크 / 의사결정 필요 사항

1. **탈퇴 시 회원 데이터 처리 정책** — hard delete vs 익명화.
   세션/수업기록은 트레이너 매출 자산이라 **PII만 제거하는 익명화**를 권장하나,
   개인정보 처리방침 문구와 일치해야 함 → 정책 확정 필요.
2. **캘린더 의존성** — 커스텀 그리드(의존성 0, 권장) vs `table_calendar`(빠름, §0 갱신 필요).
3. **문의 채널 형태** — 단일 운영 이메일 vs 센터별 문의처(테이블 컬럼 추가).
4. Edge Function `delete-account` 는 service_role 사용 → 시크릿/권한 범위 최소화 검토.
